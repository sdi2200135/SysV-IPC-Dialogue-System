SysV IPC Dialogue System

Σύστημα inter-process communication σε Linux, βασισμένο σε shared memory και System V semaphores για συντονισμένη ανταλλαγή μηνυμάτων μεταξύ πολλαπλών διεργασιών.

C (gcc -Wall -Wextra) Shared Memory Semaphores SysV IPC

📖 Σχετικά με την Εργασία

Η παρούσα εργασία αποτελεί την 1η Προγραμματιστική Εργασία του μαθήματος «Λειτουργικά Συστήματα». Υλοποιεί ένα σύστημα dialogue-based επικοινωνίας όπου κάθε διεργασία μπορεί να:

💬 Δημιουργήσει ή να συμμετάσχει σε διάλογο

Κάθε διάλογος έχει μοναδικό ID και ξεχωριστό χώρο στην shared memory.

📤 Στείλει μηνύματα

Broadcast σε όλους τους συμμετέχοντες — το μήνυμα διαβάζεται μία φορά από τον καθένα.

📥 Λάβει μηνύματα

Διασχίζει την ουρά και λαμβάνει όλα τα μηνύματα που δεν έχει διαβάσει.

🛑 Τερματίσει τον διάλογο

Με την αποστολή TERMINATE — μόνο αφού όλοι έχουν διαβάσει όλα τα μηνύματα.

Πλήρης υλοποίηση: Η εργασία καλύπτει όλες τις απαιτήσεις της εκφώνησης — δημιουργία/διαχείριση διαλόγων, αποστολή/λήψη μηνυμάτων, συγχρονισμός με semaphores, καθαρισμός πόρων.

🏗️ Βασικά Συστατικά

4 δομές δεδομένων + 3 semaphores ανά διάλογο. Πατήστε για λεπτομέρειες.

MSG message

Ένα μήνυμα: id, content, sender, readers array, terminated flag.

Dialog dialogue

Ένας διάλογος: id, participants, msg_queue, sem_id, actived flag.

Semaphores sync

3 semaphores ανά διάλογο: access, empty_slots, full_slots.

Shared Memory IPC

Δύο segments: Dialog_list και Dialog — κοινά για όλες τις διεργασίες.

⚡ Key Concepts

SEM_UNDO

Αυτόματη επαναφορά semaphores αν μια διεργασία τερματιστεί πρόωρα.

Circular Buffer

Η ουρά μηνυμάτων είναι κυκλική — (head + 1) % max_msgs.

Per-message Readers

Κάθε μήνυμα κρατά ποιοι το διάβασαν — εξασφαλίζει "read once per participant".

Graceful Terminate

Ο TERMINATE εκτελείται αφού όλοι οι συμμετέχοντες διαβάσουν τα πάντα.

2️⃣ MSG_queue — Ουρά Μηνυμάτων

📚 struct MSG_queue

Circular Buffer Logic

head = (head + 1) % max_msgs;  // wrap-around
tail = (tail + 1) % max_msgs;  // wrap-around
Γιατί circular: Αποδοτική χρήση μνήμης χωρίς μετακίνηση στοιχείων — γεμίζει διαδοχικά και επιστρέφει στην αρχή.

Συγχρονισμός

System V Semaphores — synchronization.c

🎯 3 Semaphores ανά Διάλογο

Για κάθε διάλογο δημιουργείται ένα semaphore set με 3 σημαφόρους. Αυτοί συντονίζουν την πρόσβαση και την ροή των μηνυμάτων.

SEMAPHORE 0

sem_access_dialog

Αποκλειστική πρόσβαση στη δομή Dialog. Εξασφαλίζει mutual exclusion κατά την ανάγνωση/εγγραφή.

Init: 1
SEMAPHORE 1

sem_empty_slots

Μετρά τα κενά slots στην ουρά μηνυμάτων. Ο producer περιμένει αν είναι 0.

Init: max_msgs (50)
SEMAPHORE 2

sem_full_slots

Μετρά τα γεμάτα slots. Ο consumer περιμένει αν είναι 0 (δεν υπάρχουν μηνύματα).

Init: 0

🧩 Macros στο common.h

Για καθαρότερο κώδικα, ορίζονται macros για κάθε λειτουργία:

// Αποκλειστική πρόσβαση στη δομή
#define LOCK(semid)   { sem_access_dialog, -1, SEM_UNDO }
#define UNLOCK(semid) { sem_access_dialog, +1, SEM_UNDO }

// Producer: περιμένει κενό slot
#define WAIT_EMPTY(semid)   { sem_empty_slots, -1, SEM_UNDO }
#define SIGNAL_EMPTY(semid) { sem_empty_slots, +1, SEM_UNDO }

// Consumer: περιμένει νέο μήνυμα
#define WAIT_FULL(semid)   { sem_full_slots, -1, SEM_UNDO }
#define SIGNAL_FULL(semid) { sem_full_slots, +1, SEM_UNDO }
SEM_UNDO: Όλες οι λειτουργίες χρησιμοποιούν SEM_UNDO. Αν μια διεργασία τερματιστεί πρόωρα, ο kernel αυτόματα επαναφέρει τις αλλαγές — αποφεύγονται deadlocks.

🔄 Producer-Consumer Pattern

Producer (αποστολέας)

WAIT_EMPTY → LOCK → Γράψε μήνυμα → UNLOCK → SIGNAL_FULL

Consumer (λήπτης)

LOCK → Διάβασε μήνυμα → UNLOCK → SIGNAL_EMPTY

Semaphore Operations

ΛειτουργίαSemaphoreΤιμήΠεριγραφή
LOCKaccess_dialog-1Μειώνει → μπλοκάρει αν 0
UNLOCKaccess_dialog+1Αυξάνει → ξεκλειδώνει
WAIT_EMPTYempty_slots-1Περιμένει κενό slot
SIGNAL_EMPTYempty_slots+1Απελευθέρωση slot
WAIT_FULLfull_slots-1Περιμένει νέο μήνυμα
SIGNAL_FULLfull_slots+1Ειδοποίηση για μήνυμα

🔑 Semaphore Key Generation

key_t key = IPC_PRIVATE + key_sem + dialog_id;

int semid = semget(key, 3, IPC_CREAT | 0666);

semctl(semid, sem_access_dialog, SETVAL, 1);          // ξεκλείδωτο
semctl(semid, sem_empty_slots,   SETVAL, max_msgs);  // όλα κενά
semctl(semid, sem_full_slots,    SETVAL, 0);          // κανένα μήνυμα
IPC_PRIVATE + key_sem + dialog_id: Εξασφαλίζει μοναδικό key για κάθε διάλογο — δύο dialogues δεν μοιράζονται semaphores.

Δημιουργία, Join, Send, Receive, Terminate

1️⃣ Εκκίνηση & Είσοδος σε Διάλογο

Κάθε νέα διεργασία συνδέεται πρώτα στη λίστα διαλόγων και από το κεντρικό μενού μπορεί:

[N] Νέος Διάλογος

Δημιουργεί νέο διάλογο με τυχαίο μοναδικό ID (100-999). Τον προσθέτει στη λίστα.

[J] Join

Εισάγει το ID υπάρχοντος διαλόγου και συνδέεται σε αυτόν.

[L] List

Εμφανίζει όλους τους ενεργούς διαλόγους με το πλήθος συμμετεχόντων.

[E] Exit

Έξοδος από το σύστημα — αποσύνδεση από τη λίστα διαλόγων.

Ροή Δημιουργίας Διαλόγου

  1. Attach στη λίσταattach_d_list(0) ή attach_d_list(1) αν είναι η πρώτη διεργασία.
  2. create_new_dialog()Lock τη λίστα, έλεγχος max_dialogs, δημιουργία τυχαίου μοναδικού ID, προσθήκη στη λίστα.
  3. attach_dialog()Δημιουργία shared memory segment για το Dialog μέσω shmget().
  4. ΑρχικοποίησηΜηδενισμός όλων των πεδίων + δημιουργία 3 semaphores.
  5. Προσθήκη συμμετέχονταadd_participant(dialog, pid) με κλειδωμένα semaphores.

2️⃣ Αποστολή Μηνύματος

Συνάρτηση: send_msg() στο msg_queue.c

  1. wait_for_space(semid)Μπλοκάρει αν δεν υπάρχει κενό slot στην ουρά (WAIT_EMPTY).
  2. d_lock(semid)Κλείδωμα της δομής Dialog για αποκλειστική πρόσβαση.
  3. Έλεγχος χώρουΑν msg_queue.count >= max_msgs → unlock + signal_new_space + return 0.
  4. Αντιγραφή μηνύματοςstrncpy() του content, set sender_pid, msg_id, terminated flag.
  5. Set participantsmsg->participants = dialog->participants_c — snapshot των συμμετεχόντων.
  6. Ο αποστολέας διαβάζει πρώτοςread_msg(msg, sender_pid) — το pid του μπαίνει στο readers array.
  7. Ενημέρωση δεικτώνhead = (head + 1) % max_msgs, count++, next_msg_id++.
  8. d_unlock + new_msg_signalΞεκλείδωμα + SIGNAL_FULL για ειδοποίηση consumers.
int send_msg(Dialog* dialog, int semid, 
             const char* cont, int sender_pid, 
             int terminated) {
    wait_for_space(semid);
    d_lock(semid);
    
    MSG* msg = &dialog->msg_queue.msgs[dialog->msg_queue.head];
    strncpy(msg->cont, cont, max_msg_length - 1);
    msg->sender_pid = sender_pid;
    msg->terminated = terminated;
    msg->participants = dialog->participants_c;
    
    read_msg(msg, sender_pid);  // ο αποστολέας "διαβάζει" πρώτος
    
    dialog->msg_queue.head = (dialog->msg_queue.head + 1) % max_msgs;
    dialog->msg_queue.count++;
    
    d_unlock(semid);
    new_msg_signal(semid);
    return 1;
}

3️⃣ Λήψη Μηνύματος

Συνάρτηση: receive_msg() στο msg_queue.c

  1. d_lock(semid)Κλείδωμα του dialog για αποκλειστική πρόσβαση.
  2. Διάσχιση ουράςΑπό tail προς head — έλεγχος για μηνύματα που δεν έχουν διαβαστεί από το receiver_pid.
  3. Έλεγχος αν έχει διαβαστείLoop στον readers[] — αν βρεθεί το pid, το μήνυμα έχει ήδη διαβαστεί.
  4. Αντιγραφήmemcpy(output, msg, sizeof(MSG)) — πλήρες αντίγραφο του μηνύματος.
  5. Σήμανση ως διαβασμένοread_msg(msg, receiver_pid) — προσθήκη pid στο readers array.
  6. Έλεγχος "read by all"Αν msg_read_by_all() επιστρέψει 1 → advance tail, count--, signal_new_space.
  7. breakΣταματάει μετά το πρώτο unread μήνυμα.
One-by-one: Η receive_msg() επιστρέφει ένα μήνυμα κάθε φορά. Η handle_receive_command() την καλεί σε loop μέχρι να μην υπάρχουν άλλα unread.

4️⃣ Τερματισμός Διαλόγου

Δύο τρόποι:

Α. Αποστολή TERMINATE

  1. send_msg με terminated=1Αποστέλλεται κανονικά ως μήνυμα με το flag.
  2. Λήψη από όλουςΚάθε συμμετέχων το διαβάζει και ελέγχει το flag.
  3. sleep(2)Μικρή καθυστέρηση για να προλάβουν όλοι να το δουν.
  4. leave_dialog()Αποχώρηση από τον διάλογο.
  5. clean_all()Αποσύνδεση από shared memory.

Β. Επιλογή [E] από μενού

  1. leave_dialog()Lock dialog, remove_participant(pid).
  2. Έλεγχος πλήθουςΑν participants_c == 0 → remove_dialog από λίστα.
  3. destroy_d_sem + destroy_dialogΔιαγραφή semaphores και shared memory.
  4. detach + clean_allΑποσύνδεση από όλα τα segments.
Graceful Termination: Ο διάλογος δεν διαγράφεται μέχρι να διαβαστεί το TERMINATE από όλους τους συμμετέχοντες. Αυτό εξασφαλίζει ότι κανείς δεν χάνει μηνύματα.

Συνάρτηση: list_active_dialogs()

void list_active_dialogs(Dialog_list* d_list) {
    semop(d_list->sem_id, &lock_op, 1);  // lock λίστας
    
    for (int i = 0; i < d_list->active_c; i++) {
        Dialog* dialog = attach_dialog(d_list->dialog_ids[i], 0);
        if (dialog) {
            printf("ID: %d | Συμμετέχοντες: %d\n", 
                   dialog->dialog_id, dialog->participants_c);
            detach_dialog();
        }
    }
    
    semop(d_list->sem_id, &unlock_op, 1);  // unlock λίστας
}

💾 Δύο Shared Memory Segments

Dialog_list Segment

Ένα global segment που περιέχει τη λίστα όλων των ενεργών διαλόγων. Δημιουργείται από την πρώτη διεργασία.

void sign_handler(int signum) {

Design Choices

Σχεδιαστικές αποφάσεις και αιτιολόγηση

1️⃣ Readers per Message

Κάθε MSG περιέχει πίνακα readers[] και μετρητή readers_c. Όταν μια διεργασία διαβάσει το μήνυμα, το pid της προστίθεται στον πίνακα.

Γιατί;

  • Εξασφαλίζει ότι κάθε μήνυμα διαβάζεται ακριβώς μία φορά από κάθε συμμετέχοντα.
  • Επιτρέπει στη msg_read_by_all() να ελέγχει αν το μήνυμα μπορεί να αφαιρεθεί από την ουρά.
  • Δεν απαιτείται κεντρικός coordinator — κάθε MSG "ξέρει" ποιοι το διάβασαν.

2️⃣ Circular Message Queue

Αντί για shifting στοιχείων, χρησιμοποιούνται δείκτες head/tail με modular arithmetic.

Πλεονεκτήματα

  • O(1) push/pop αντί για O(n) shifting.
  • Σταθερή χρήση μνήμης — τα 50 slots ανακυκλώνονται.
  • Εύκολος έλεγχος πληρότητας: count == max_msgs.

3️⃣ Graceful TERMINATE

Ο τελευταίος συμμετέχων που διαβάζει το TERMINATE είναι υπεύθυνος για τον καθαρισμό των πόρων.

Εγγύηση: Ο διάλογος δεν διαγράφεται μέχρι όλοι οι συμμετέχοντες να διαβάσουν όλα τα μηνύματα, συμπεριλαμβανομένου του TERMINATE.

Ροή

Send TERMINATE → Όλοι διαβάζουν → remove_participant → participants_c == 0 → destroy_dialog

4️⃣ SEM_UNDO σε όλα τα Semaphores

Όλες οι semaphore λειτουργίες χρησιμοποιούν SEM_UNDO.

Γιατί;

Αν μια διεργασία τερματιστεί ενώ κρατάει LOCK, ο kernel αυτόματα επαναφέρει τη τιμή. Χωρίς αυτό, το σύστημα θα οδηγούνταν σε deadlock — κανείς δεν θα μπορούσε να ξεκλειδώσει το dialog.

5️⃣ Attach με is_X Flags

Κάθε segment έχει flags is_list / is_dialog που δείχνουν αν η τρέχουσα διεργασία το δημιούργησε.

Χρήση

  • Το destroy_*() ελέγχει το flag πριν διαγράψει.
  • Αποφεύγεται διπλή διαγραφή από πολλαπλές διεργασίες.
  • Μόνο η "ιδιοκτήτρια" διεργασία μπορεί να κάνει cleanup.

6️⃣ Signal Handlers για Cleanup

Οι handlers SIGINT και SIGTERM καλούν leave_dialog() και clean_all().

Πλεονέκτημα

Ακόμα και αν ο χρήστης πατήσει Ctrl+C, η διεργασία:

  1. Αποχωρεί από τον διάλογοΑφαιρεί το pid από τη λίστα συμμετεχόντων.
  2. Ελέγχει αν ήταν ο τελευταίοςΑν ναι, διαγράφει τον διάλογο.
  3. Αποσυνδέεται από shared memoryΔεν αφήνει segments attached.

📊 Trade-offs

ΑπόφασηΠλεονέκτημαΜειονέκτημα
Fixed-size arrays Απλός, predictable κώδικας Σταθερά limits (50 msgs, 50 participants)
Per-dialogue semaphores Απομονωμένος συγχρονισμός Πολλά IPC resources σε πολλούς διαλόγους
Copy-based messages Isolation — δεν μοιράζονται pointers Κόστος αντιγραφής για μεγάλα μηνύματα
Busy loop για terminate Απλός κώδικας, εγγυημένη παράδοση 2-second delay πριν τον τερματισμό

🏁 Σύνοψη

Το σύστημα χρησιμοποιεί κλασικές τεχνικές IPC των System V — shared memory και semaphores — για να υλοποιήσει ένα dialogue-based messaging system.

Οι σχεδιαστικές αποφάσεις (per-dialogue semaphores, SEM_UNDO, graceful terminate) δίνουν αξιοπιστία και αποφυγή deadlocks, ενώ τα fixed-size arrays κρατούν τον κώδικα απλό και κατανοητό.
